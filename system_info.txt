5. PUBLIC CONTENT API
================================================================================

Envelope:
  Muvaffaqiyat : { "status": "ok", "data": ... }
  Xato        : { "status": "error", "message": "...", "code": "..." }

5.1. GET /api.php/health
    GET /api.php/status
    -> 200 { "status": "ok" }

5.2. GET /api.php/profile?lang=uz|en|ru
    -> data:
       { name, role, bio, quick_text, location, email, github, telegram,
         telegram_handle, avatar_url }
    Noto'g'ri lang -> uz.
    DB yo'q -> 503 db_unavailable.

5.3. GET /api.php/projects?lang=...
    -> data: [
         { slug, category, tag, title, summary, tech[], repo_url, demo_url,
           image_url, detail_url }
       ]
    Faqat is_active = 1; sort_order bo'yicha.
    tech — JSON massiv.

5.4. GET /api.php/projects/{slug}?lang=...
    -> yuqoridagi maydonlar + description, results[], stack_notes[]
    Topilmagan slug -> 404 project_not_found.
    Slug formati: /^[a-z0-9-]{1,80}$/.

5.5. GET /api.php/websites
    X-Api-Token: <token> yoki Authorization: Bearer <token>
    Token tartibi: API_TOKEN -> SITEHUB_API_TOKEN -> OTABOYEV_API_TOKEN.
    Faqat APP_ENV=local|development|test da `otaboyev-dev-token` fallback.
    Noto'g'ri/yo'q token -> 401.
    Productionda haqiqiy token berilmasa endpoint 401 qaytaradi.

5.6. POST /api.php/form_container/submit
    Contact form va Sitejet form proxy.
    id=contact -> native handler (contact_messages).
    Boshqa id -> form_<id>[ed-f-N] Sitejet kontrakti bo'yicha proxy.

5.7. GET /api.php/bot/health
    -> 200 { status:"ok", data:{ configured, webhook_secret, imap, database } }
    Faqat booleanlar; token/secret/parol/email qiymati yo'q.
    Boshqa method -> 405 Allow: GET.
    Yon ta'sirsiz; bot_alert_admin chaqirmaydi.

5.8. POST /api.php/bot/webhook
    X-Telegram-Bot-Api-Secret-Token tekshiriladi.
    Faqat `message` update'lari; secret yo'q/noto'g'ri -> 403.
    GET -> 405 Allow: POST.
    Body > 131072 bayt -> 413.
    update_id idempotentligi bot_updates_seen orqali.

5.9. Proxy fallback
    Boshqa /api.php/* -> https://api.sitehub.io
    /images* -> https://inter-cdn.com

CORS:
  - Faqat /profile, /projects, /projects/{slug}, /health, /status uchun
    Access-Control-Allow-Origin: * va GET, OPTIONS.
  - form, admin, bot, websites endpointlarida CORS header yo'q.
  - .htaccess qo'shimcha himoya sifatida admin|bot|form_container|websites
    javoblaridan CORS headerlarini o'chiradi.

6. ADMIN API VA AUTH
================================================================================

6.1. Admin auth oqimi

  1) /admin/ Telegram Login Widget
  2) GET /api.php/admin/auth/telegram
     - Telegram HMAC imzosi tekshiriladi
     - auth_date 300 soniya oynasida bo'lishi kerak
     - admin_users.telegram_id va is_active=1 tekshiriladi
     - challenge cookie (HttpOnly, SameSite=Lax) beriladi
  3) Emailga 6 xonali OTP yuboriladi
     - amal muddati 600 soniya
     - 5 noto'g'ri urinishdan keyin 429
     - OTP HMAC bilan hashlanadi
  4) POST /api.php/admin/auth/verify
     - muvaffaqiyatli bo'lsa admin_session cookie (HttpOnly, Secure HTTPS,
       SameSite=Strict) va CSRF token beriladi
  5) GET /api.php/admin/session har so'rovda admin_users bilan JOIN qiladi;
     rol o'zgarsa darhol kuchga kiradi.

  Rate limit:
    - 15 daqiqada 3 ta login challenge
    - 15 daqiqada 5 ta login start
    - 5 ta OTP urinishi
    - 429 rate_limited / too_many_attempts

  Session:
    - absolute TTL 43200 s (12 soat)
    - idle TTL 1800 s (30 daqiqa), 300..43200 oralig'iga clamp
    - last_seen_at yangilanadi
    - logout bitta sessiyani, logout-all barcha sessiyalarni o'chiradi

Saqlash:
  - contact_messages jadvali
  - payload — barcha form maydonlari + attachment metadata JSON
  - ip_hash — IP'ning hash'i (ochiq IP saqlanmaydi)
  - user_agent — qisqartirilgan
  - is_read — 0/1

Bildirishnoma:
  - best-effort email: admin.email manziliga `Yangi kontakt xabari: ...`
  - best-effort Telegram: faol adminlarga (ko'pi bilan 10 ta)

  - GET /admin/messages?count=1 -> unread count
  - GET /admin/messages?unread=1 -> faqat o'qilmaganlar

9. MA'LUMOTLAR BAZASI
================================================================================

DB turi        : MySQL / InnoDB
Charset        : utf8mb4, utf8mb4_unicode_ci
Jadvallar      : 12 ta
Foreign key    : 5 ta
Asosiy jadval  : profiles (id=1)

9.1. Jadvalar

  profiles
    id, name, email, github, telegram, telegram_handle, avatar_url,
    updated_at
    PK: id
    Izoh: bitta profil (id=1).

  profile_translations
    profile_id, lang, role, bio, quick_text, location
    PK: (profile_id, lang)
    FK: profile_id -> profiles.id ON DELETE CASCADE
    Lang: uz, en, ru.

  projects
    id, slug, category, repo_url, demo_url, image_url, sort_order,
    is_active, created_at, updated_at
    PK: id
    UNIQUE: slug
    INDEX: idx_projects_active_sort (is_active, sort_order)

  project_translations
    project_id, lang, tag, title, summary, description, tech, results,
    stack_notes
    PK: (project_id, lang)
    FK: project_id -> projects.id ON DELETE CASCADE
    tech/results/stack_notes — JSON matn (TEXT), PHP'da json_decode.

  contact_messages
    id, form_id, locale, name, email, subject, message, payload, ip_hash,
    user_agent, is_read, created_at
    PK: id
    INDEX: idx_contact_messages_unread (is_read, created_at)
    INDEX: idx_contact_messages_created (created_at)
    INDEX: idx_contact_messages_ip (ip_hash, created_at)
    payload — JSON: maydonlar + attachment metadata.

  admin_users
    id, telegram_id, email, display_name, telegram_username, is_active,
    role, last_login_at, created_at, updated_at
    PK: id
    UNIQUE: telegram_id
    INDEX: idx_admin_users_active (is_active)
    INDEX: idx_admin_users_role (role)
    role: 'super' yoki 'admin'

  admin_login_challenges
    id, admin_id, challenge_hash, code_hash, email, attempts, expires_at,
    consumed_at, ip_hash, created_at
    PK: id
    UNIQUE: challenge_hash
    INDEX: (admin_id, created_at), (expires_at)
    FK: admin_id -> admin_users.id ON DELETE CASCADE

  admin_sessions
    id, admin_id, token_hash, expires_at, last_seen_at, ip_hash,
    user_agent, created_at
    PK: id
    UNIQUE: token_hash
    INDEX: admin_id, expires_at
    FK: admin_id -> admin_users.id ON DELETE CASCADE

  admin_auth_events
    id, event_type, telegram_id, ip_hash, created_at
    PK: id
    INDEX: (event_type, created_at), (telegram_id, created_at)

  admin_audit_log
    id, admin_id, action, entity, entity_id, ip_hash, details, created_at
    PK: id
    INDEX: (admin_id, created_at), (action, created_at)
    FK: admin_id -> admin_users.id ON DELETE SET NULL

  bot_updates_seen
    update_id, seen_at
    PK: update_id
    INDEX: seen_at

  bot_rate_limit
    id, admin_id, command, created_at
    PK: id
